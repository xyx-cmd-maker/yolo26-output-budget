# Reallocating a detector's output budget is positional

Code and derived results for the manuscript *Reallocating a detector's output budget is
positional: it replaces the worst image, and only when that image is quota-limited*
by Yuxuan Xia and Ziming Zeng, Shenzhen Polytechnic University.

## What the study measures

Object detectors emit a bounded number of boxes per image, and that bound is usually one
constant applied to every image. This work asks what happens when a fixed total box budget
is redistributed between images rather than raised for all of them.

The main finding is positional. Worst-image recall rises because a different image becomes
the minimum, not because the same image improves. The gain appears on the validation split,
does not appear on the held-out test split, and depends on whether the worst image is
limited by its quota or by the detector.

The allocation pipeline uses ground-truth information throughout and is not a deployable
policy. A deterministic top-up step reads true-positive matches to decide which image
receives the next box. Every comparison in the paper is therefore an offline diagnostic on
both splits. This is stated in the Methods, in the section titled Test-set evaluation and
label dependence.

## Reproducing the results

    pip install -r requirements.lock.txt
    python scripts/check_all.py
    python scripts/recompute_manuscript_numbers.py
    python scripts/build_submission_pdf.py
    python scripts/build_supplementary.py

`scripts/check_all.py` is the single entry point. It reruns every consistency and numerical
check used for the paper, including independent recomputation of the reported statistics
from the stored per-image records. It must pass before any deliverable is rebuilt.

## Where the numbers come from

`results/tables/manuscript-numbers.json` holds every number quoted in the manuscript.
`results/tables/fwer-and-equivalence.json` holds the Holm step-down and TOST results.
`results/tables/holm-detail.json` holds the per-condition ranks, raw p values, thresholds
and adjusted p values.
`results/tables/quintile-ci.json` holds the per-band bootstrap intervals.
`results/tables/testdev-worst-image.json` holds the held-out worst-image audit.
`results/tables/table5-structural.json` holds the structural audit.
`results/tables/gt-cap-sensitivity.json` holds the sensitivity analysis to the label-count
cap.
`results/tables/negative-results.md` records the negative results.

## What is not in this repository

The datasets are not redistributed, because their licences forbid it. VisDrone2019-DET is
distributed under CC BY-NC-SA 3.0 for academic use; COCO 2017 and CrowdHuman are public.
Model weights are not included, because of size; they can be rebuilt with the training
settings recorded in the manuscript. The per-image prediction records that the reported
numbers are computed from total 76 MB and are regenerated by
`scripts/run_decision_rule.py` from the trained weights.

A fresh clone can therefore run most of `scripts/check_all.py` but not all of it, and the
script says so rather than failing: with no prediction records present it prints
`20 / 23 checks passed, 3 skipped` and names the checks that need them; once the records
are generated it prints `all 23 checks passed`. Reproducing end to end needs the weights or
a retraining run: three seeds, 100 epochs each, on a single 8 GB consumer GPU.

## Study design

Detector: YOLO26n from Ultralytics 8.4.177, with two prediction heads, one-to-many with
NMS and one-to-one without.

Dataset: VisDrone2019-DET, 10 classes, 548 validation images with 38,759 annotated objects
in total, and 1,610 test-dev images.

Training: initialised from COCO weights, 100 epochs at 640 by 640, batch size 8. Validation
mAP50 is 0.3436, 0.3407 and 0.3421 for seeds 42, 43 and 44.

Budget: the total budget is S equal to B times N. B is an average per-image budget and not
a cap, because a reallocation may give one image far more than B and another far less.

Primary metric: worst-image recall, the minimum over images of the per-image recall.
